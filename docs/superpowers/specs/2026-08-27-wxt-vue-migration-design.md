# WXT / Vue 渐进式迁移设计

日期：2026-08-27
状态：已选定方案 B，等待实施计划

## 背景

当前稳定版本是在 Edge 中直接加载项目根目录的 Manifest V3 扩展。它已经支持 PDF、EPUB、MOBI、AZW3、连续滚动、搜索、高亮、批注、备份恢复和升级回滚，并以根目录版的真实 Edge E2E 作为发布门禁。

仓库内已经存在 WXT、Vue 3、TypeScript 和 Pinia 外壳，但 `entrypoints/reader/main.ts` 仍会导入旧的 `src/reader.js`，`legacy-bridge.ts` 通过 `MutationObserver` 从 DOM 反向同步少量 Pinia 状态。Vue 组件目前主要提供旧控制器依赖的 DOM 节点，并未真正拥有阅读器行为。

根目录 Manifest 与 WXT 配置使用同一固定公钥，扩展 ID 可以保持一致；两者也使用相同的 `quiet-reader` IndexedDB、`books` / `meta` 对象仓库和 localStorage 设置。因此迁移应采用同扩展来源的原地升级，不创建第二套书库，也不要求复制所有书籍 Blob。

## 决策

采用渐进式“绞杀者迁移”：WXT/Vue 先成为可验收的构建与应用外壳，再按领域逐块接管旧控制器。每个阶段保持根目录稳定版可用，只有 WXT 通过全部功能、数据和真实 Edge 验收后，才删除旧入口与桥接代码。

不采用一次性重写，因为它会同时改变扩展打包、界面事件、EPUB/PDF 引擎和持久化路径，难以定位回归。也不采用仅更换打包器的方案，因为它不能消除 DOM 查询、全局状态和旧控制器带来的维护成本。

## 目标

- WXT 成为唯一构建、开发和最终发布入口。
- Vue 组件拥有界面渲染和用户事件，不再依赖旧控制器查询固定 DOM ID。
- Pinia 管理当前会话的可观察状态，但不直接持久化书籍 Blob、批注或数据库记录。
- Repository、Service 和 ReaderAdapter 管理持久化与阅读引擎边界。
- 根目录版书籍、进度、批注和设置在同扩展 ID 下被 WXT 原地读取。
- 迁移过程可备份、可验证、可回滚，不提前升级数据库 schema。
- EPUB、MOBI、AZW3、PDF、搜索、批注和连续滚动能力不回退。

## 非目标

- 本迁移不恢复 AI 界面或网络请求路由；AI 保持关闭。
- 本迁移不增加云同步、账号、OCR、语义搜索或新的阅读功能。
- 本迁移不重新设计现有视觉语言；首先追求功能、数据和交互等价。
- 在 WXT 完成切换前不删除根目录稳定版发布与回滚能力。

## 目标架构

### 界面层

Vue 组件负责渲染、可访问语义和用户事件。组件只读取 Pinia 状态并调用应用层动作，不直接导入 Foliate.js、PDF.js、IndexedDB 实现或旧 `reader.js`。

Pinia 按职责拆分运行时状态：

- `library`：书架摘要、选择状态、加载和错误；书籍 Blob 仍由 Repository 持有。
- `session`：当前书籍、格式、章节、进度、流模式和加载状态。
- `panels`：目录、设置、工具、对话框和顶部栏状态。
- `searchAnnotations`：当前查询、结果、选区和当前书籍的批注视图。

### 应用层

应用层通过明确接口编排用户操作：

- `LibraryService`：列出、导入、删除、备份和恢复书籍。
- `ReaderSessionController`：打开、关闭、跳转、翻页、切换流模式和恢复进度。
- `SettingsService`：读取、校验和保存非敏感设置。
- `AnnotationService`：创建、更新、删除、筛选、导入导出和锚点恢复。
- `SearchService`：协调电子书会话索引和 PDF 文本搜索。

服务返回结构化结果或领域错误，Vue 不解析引擎异常文本。

### 引擎层

Foliate.js 与 PDF.js 继续隐藏在 ReaderAdapter 后面：

- `EbookReaderAdapter` 管理 EPUB/MOBI/AZW3 的视图、CFI、目录、选区和连续滚动。
- `PdfReaderAdapter` 管理文档、页面、文本层、缩放、跳页和矩形重建。
- 两种适配器向 `ReaderSessionController` 发出统一的进度、位置、目录、选区和错误事件。

引擎允许操作必要的宿主节点或 Canvas，但这些节点通过 Vue `ref` 明确传入，不再由模块全局查询。

### 持久化层

现有 `BookRepository`、`ProgressService`、备份恢复和 schema 迁移注册表继续作为唯一持久化入口。Pinia 中的书架和批注数据只是 Repository 数据的会话投影，刷新后必须重新读取，不形成第二事实来源。

## 过渡边界

迁移期间保留一个显式 `LegacyReaderPort`，用于把尚未迁移的用户动作和引擎事件连接到旧控制器。它必须通过函数和事件传递结构化数据，不再增加新的 DOM `MutationObserver` 依赖。

每迁移一个领域，就从旧 `reader.js` 删除对应监听器和状态所有权。`legacy-bridge.ts` 的允许职责只会减少，最终删除。任何新功能只能进入新的 Vue / Service / Adapter 路径，不能继续扩展旧控制器。

## 数据继承与迁移

### 同源继承

WXT Manifest 必须保留与根目录 Manifest 完全相同的公钥、扩展名、版本策略和存储权限。自动化测试要比较两种构建的扩展 ID，并在同一个持久化 Edge 用户目录中依次加载根目录版和 WXT 版。

WXT 首次启动时执行只读预检：

1. 打开 `quiet-reader` 数据库，不触发 schema 升级。
2. 验证 `books` 和 `meta` 仓库存在。
3. 读取 schema 元数据、书籍数量和关键字段。
4. 验证书籍 Blob、进度与批注可读取，但不批量重写记录。
5. 读取并校验 localStorage 设置；未知字段保留，非法字段回退到默认值。

数据库在整个迁移期保持 schema v2。若后续功能确实需要新 schema，必须在根目录入口停用后另立设计，并提供双向兼容或明确不可回滚门禁。

### 备份与回滚

切换 WXT 稳定版前，发布流程要求用户从根目录版生成 `.quietreader` 备份。WXT 必须能导入同一备份格式，并在导入前校验版本、schema 与 SHA-256。

因为迁移期不升级数据库 schema，回滚流程是重新加载同扩展 ID 的根目录稳定版。自动化测试必须覆盖：

1. 根目录版写入真实书籍、设置、进度和批注。
2. 关闭浏览器后使用同一用户目录启动 WXT 版。
3. WXT 读取并继续修改同一数据。
4. 再次关闭浏览器并回滚根目录版。
5. 根目录版读取 WXT 修改后的兼容数据。

预检失败时 WXT 进入持久错误页，提供“导出诊断”“恢复备份”和“返回书架”入口，不清空数据库、不自动覆盖记录。

## 分阶段迁移

### 阶段 A：双入口等价基线

- 固定根目录版与 WXT 版 Manifest、资源路径和扩展 ID 契约。
- 为 WXT 增加与根目录版同样的真实文件 E2E 入口。
- 记录所有功能、DOM 事件和持久化写入的所有权清单。
- 验收 WXT 能加载四种格式，但暂时允许旧控制器驱动行为。

### 阶段 B：数据连续性门禁

- 实现只读迁移预检与结构化错误。
- 建立根目录版到 WXT 再回滚的持久 Edge E2E。
- 验证书籍 Blob、设置、进度、高亮、批注和 schema 元数据。
- 在数据连续性验收通过前禁止迁移任何持久化格式。

### 阶段 C：Vue 接管书架、面板与设置

- Vue / Pinia 接管书架加载、打开文件、删除、备份恢复和面板状态。
- 移除这些领域的 DOM 反向同步和旧事件监听器。
- 保持阅读引擎暂由 LegacyReaderPort 驱动。

### 阶段 D：Vue 接管电子书会话

- `ReaderSessionController` 与 `EbookReaderAdapter` 接管 EPUB/MOBI/AZW3。
- 迁移目录、进度、分页、连续滚动、主题排版和选区事件。
- 保留现有 CFI、文本锚点、章节窗口与性能行为。

### 阶段 E：Vue 接管 PDF 会话

- `PdfReaderAdapter` 接管 PDF 加载、文本层、缩放、跳页和进度。
- 保留隐藏容器防护、按需渲染和批注矩形重建行为。

### 阶段 F：Vue 接管搜索与批注

- 迁移跨章节搜索、取消、句子上下文、高亮、批注组织和导入导出。
- 保留未解析锚点不绘制、受限恢复和批量操作约束。

### 阶段 G：切换与清理

- 删除 `MutationObserver` 桥接、已迁移的旧控制器和重复 DOM 入口。
- WXT 发布包通过根目录版的全部检查、单测和真实 Edge E2E。
- 完成人工 Edge 连续使用验收后，将 WXT 标记为稳定入口。
- 保留最后一个根目录稳定 ZIP、校验和、备份说明和回滚步骤。

## 错误处理

- 所有打开失败继续使用统一错误分类，不能退化为空白页或无限加载。
- Service 与 Adapter 抛出带代码、阶段和可恢复性的结构化错误。
- Vue 错误页必须保留当前书库，不因单本书失败重置全局状态。
- 迁移或预检错误禁止执行删除、清空、批量重写或 schema 升级。
- 旧入口和新入口对相同损坏文件必须给出等价的用户提示。

## 测试策略

### 单元与组件测试

- Service、Adapter 和 Store 的状态转换使用 Vitest 测试。
- Vue 组件测试真实事件、可访问名称和状态渲染，不断言实现细节。
- 每次旧职责移除前，先有新接口的失败测试，再迁移实现。
- 架构测试禁止 Vue 组件直接导入 Foliate.js、PDF.js、IndexedDB 或旧控制器。

### 构建与包测试

- `npm run build` 必须生成可加载的 WXT Manifest V3 目录。
- 校验 PDF worker、cmaps、standard fonts、wasm、Foliate 资源和图标路径。
- WXT 包不能包含测试、根目录重复入口或开发缓存。

### 真实 Edge E2E

- 所有根目录版 25 个 E2E 场景逐步增加 WXT 运行目标。
- 四种格式必须验证打开、目录、导航、搜索、批注和进度恢复。
- 连续滚动、真实中文、真实插图、超大 EPUB、损坏文件和 PDF 文本层必须保持现有基线。
- 使用持久用户目录验证根目录版到 WXT 的升级和回滚。
- 自动化通过后仍需要用户在实际 Edge 配置中连续使用验收。

## 每阶段交付规则

- 每个阶段先写失败测试，再实现最小可验收切片。
- 每个阶段执行静态检查、全部单元测试、相关 WXT E2E 和发布包校验。
- 数据、引擎或入口变更必须执行完整根目录与 WXT E2E。
- 每个阶段独立代码审查、提交并推送到 `main`。
- 发现数据丢失、扩展 ID 变化、空白正文或无法回滚时立即停止后续迁移。

## 完成门禁

只有同时满足以下条件，WXT/Vue 迁移才算完成：

- WXT 是唯一运行入口，Vue 拥有全部用户界面事件和状态渲染。
- `legacy-bridge.ts`、DOM `MutationObserver` 和旧阅读控制器已删除。
- WXT 与根目录版扩展 ID 相同，现有书库无需复制即可读取。
- 根目录到 WXT 再回滚的数据连续性 E2E 通过。
- PDF、EPUB、MOBI、AZW3、连续滚动、搜索、高亮、批注和备份恢复全部通过真实 Edge 验收。
- AI 入口和网络请求继续保持关闭。
- 用户完成实际 Edge 连续使用验收，并确认无阻断回归。
