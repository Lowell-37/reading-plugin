# 批注锚点稳定性与跨章节搜索设计

日期：2026-08-03  
状态：已确认，待实施

## 目标

按顺序完成三个可独立验收和发布的增量：

1. 保证同一本文件在重启阅读器、修改字号、行高、页面宽度以及 PDF 缩放后，高亮和批注仍定位到原文。
2. 允许通过版本化 JSON 将批注导入内容有所变化的新版书籍，并在可信时恢复位置；不可信时明确标记为需要重新定位。
3. 提升 EPUB、MOBI、AZW3 跨章节搜索速度、取消响应和上下文质量。

每个增量必须先通过对应单元测试、根目录 Microsoft Edge E2E 和全量回归，再独立提交并推送。稳定运行入口保持为 `D:\projects\reading-plugin` 根目录，不处理 `.output/chrome-mv3`。

## 非目标

- 不实现云同步、多人协作或跨设备实时同步。
- 不为扫描版 PDF 增加 OCR。
- 不建立持久化全文搜索数据库或向量索引。
- 不在本阶段迁移 WXT/Vue 运行入口。
- 不对低置信度匹配静默创建高亮。

## 方案选择

采用分层文本锚点。结构定位信息负责快速精确恢复，文本引文负责排版变化和轻微内容变化后的回退。相比仅保存 CFI、页码与矩形，此方案能抵抗布局变化；相比立即建立整本书模糊索引，它更容易控制性能、存储和误匹配风险。

## 数据模型

在现有 `Annotation` 上增加可选、向后兼容的 `anchor`：

```ts
interface TextQuoteAnchor {
  exact: string
  prefix: string
  suffix: string
  normalizedExact: string
}

interface EbookAnnotationAnchor {
  version: 1
  kind: 'ebook'
  section: number | null
  cfi: string | null
  textOffset: number | null
  quote: TextQuoteAnchor
}

interface PdfAnnotationAnchor {
  version: 1
  kind: 'pdf'
  page: number
  textOffset: number | null
  quote: TextQuoteAnchor
}
```

现有 `locator`、`page`、`section` 和 `rects` 保留，确保旧数据、旧导出文件和 Foliate/PDF 当前渲染路径继续工作。旧批注不做破坏性数据库迁移；成功解析后在下一次保存时惰性补充 `anchor`。

批注增加可选状态 `anchorStatus: 'resolved' | 'unresolved'`。只有内容变化后的恢复失败或不唯一时写入 `unresolved`；同一文件的正常旧批注不因缺少新字段而直接判定失败。

## 第一增量：同一文件稳定恢复

### EPUB、MOBI 与 AZW3

创建批注时保存 Foliate 返回的 CFI、章节号、章节规范化文本偏移，以及原文前后各最多 48 个字符。恢复按以下顺序执行：

1. 使用原 CFI 定位并核对选中文字。
2. CFI 可解析但原文不一致时，在同一章节中按规范化文本偏移查找。
3. 偏移失效时，在同一章节搜索 `exact`，用 `prefix` 和 `suffix` 消除重复文本歧义。
4. 只有唯一可信候选才更新运行时定位，并在保存时回写新的 CFI 和偏移。

字体、行高和页面宽度只改变布局，不改变章节文本锚点。连续滚动和分页模式共享同一个无 DOM 锚点解析核心，渲染适配层只负责取得章节文本、创建范围和显示高亮。

### PDF

创建批注时将浏览器选区映射到 PDF.js 页面文本层，保存页码、页面规范化文本偏移、引文上下文和当前矩形。恢复按以下顺序执行：

1. 在原页按文本偏移和原文核对。
2. 偏移不一致时在原页按 `exact + prefix + suffix` 找唯一候选。
3. 根据当前文本层重新计算矩形，不复用缩放前的像素坐标。

PDF 缩放后重建文本层与高亮矩形；页码和文本锚点不变。无法找到可信候选时保留批注列表记录，但不显示错误位置的覆盖层。

## 第二增量：内容变化后的受限恢复

入口沿用版本化 JSON 导入。书名或文件名不一致仍需用户确认，确认后对导入批注执行：

1. 首先在原章节或原 PDF 页执行精确引文匹配。
2. 原位置失败时，电子书只搜索原章节相邻章节；PDF 只搜索原页前后各两页。
3. 精确原文不存在时，使用规范化原文相似度加前后文相似度评分。
4. 候选必须唯一，且综合置信度不低于 0.86；最高候选与第二候选分差必须至少为 0.08。
5. 达不到条件时设置 `anchorStatus: 'unresolved'`，保留原文、批注、标签和旧位置，不自动绘制高亮。

批注列表显示“需要重新定位”，并允许用户点击后回到旧章节或页码附近。手动重新选择并绑定属于后续增强，本阶段不增加新的复杂交互。

## 第三增量：跨章节搜索

新增会话级 `EbookSearchIndex`，按书籍打开周期存在于内存：

- 首次搜索按阅读顺序懒加载章节文本，并缓存规范化文本和原始文本映射。
- 同一书籍的后续搜索复用缓存，不写入 IndexedDB。
- 每次搜索持有运行编号或 `AbortSignal`；新搜索开始时，旧搜索立即停止追加结果。
- 结果分批推送到现有列表，优先显示当前章节和已缓存章节，再继续后台扫描。
- 每条结果包含章节、原文偏移、匹配长度、前后文和可跳转 locator；跳转前再次核对原文。
- 上下文以完整句子边界为优先，无法识别句子时回退到匹配前后各 60 个字符；连续空白规范化为单空格。

PDF 搜索保留现有按页缓存方式，但统一复用上下文生成和取消机制，确保 EPUB 与 PDF 的结果表现一致。

## 模块边界

- `src/core/text-anchor.ts`：文本规范化、引文创建、候选评分和唯一候选选择，不依赖 DOM。
- `src/core/search-context.ts`：句子优先的上下文截取和原始偏移映射。
- `src/core/ebook-search-index.ts`：会话级章节缓存、取消和分批结果。
- `src/core/types.ts`：锚点与解析状态类型。
- `src/reader.js`：把 Foliate/PDF.js 选区、章节文本和页面文本接到核心模块，处理 UI 状态。
- `src/continuous-ebook.js`：连续模式中解析锚点、重建范围和高亮。

核心模块必须可单元测试；DOM 范围与 Foliate/PDF.js 集成使用根目录 Edge E2E 验证。不要把模糊匹配或上下文算法继续堆进 `src/reader.js`。

## 错误处理与数据安全

- 新字段全部可选，读取旧数据不得抛错或删除记录。
- 导入文件的现有 10 MB、10000 条限制继续生效。
- 锚点恢复失败不修改原批注内容，不覆盖本地更新时间更新的记录。
- 模糊匹配只接受唯一高置信候选；宁可显示未解析状态，也不高亮错误文本。
- 搜索章节解析失败时记录该章节错误并继续其他章节；取消搜索不显示错误提示。

## 测试与验收

### 单元测试

- 文本规范化保持可预测的原始偏移映射。
- 重复引文通过前后文和最近偏移消歧。
- 低置信度、并列候选和空文本返回未解析。
- 旧批注规范化后保持兼容，新锚点可导入导出。
- 句子边界上下文、中文标点、英文标点和空白规范化正确。
- 搜索缓存只加载章节一次，新搜索取消旧搜索，分批顺序稳定。

### 根目录 Edge E2E

- EPUB 批注在字号、行高、页面宽度切换和重启后仍命中相同原文。
- EPUB 在分页与连续滚动之间切换后仍恢复相同高亮。
- PDF 批注在缩放、重渲染和重启后重新计算矩形并命中相同文本。
- 将批注 JSON 导入轻微修改的测试书时，高置信候选恢复；重复或低置信候选标记未解析。
- EPUB、MOBI、AZW3 长书搜索可被下一次搜索取消，缓存搜索返回可靠上下文并正确跳转。

### 每个增量的提交门禁

1. 先写失败测试并确认因缺少目标行为而失败。
2. 实现最小功能使定向测试通过。
3. 运行 `npm run check`、`npm test` 和相关 Edge E2E。
4. 运行完整 `npm run test:e2e`。
5. 更新 `README.md` 与 `docs/ROADMAP.md`，再独立提交并推送。

## 实施顺序

1. 同一文件锚点模型、EPUB/PDF 创建与恢复、排版变化 E2E。
2. 内容变化后的受限模糊恢复、未解析状态与导入 E2E。
3. 会话级跨章节搜索缓存、取消、上下文与多格式 E2E。

前一增量全部验收并推送后，自动进入下一增量。
