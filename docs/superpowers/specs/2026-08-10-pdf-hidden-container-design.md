# PDF 页面不可见修复设计

## 背景与根因

根目录扩展能够解析并渲染测试 PDF 和用户提供的 220 页扫描版 PDF。诊断中，第一页 canvas 已包含非空图像像素，但 `#pdf-viewport` 的顶部位于 `#reader-stage` 底部之外。

`#ebook-host` 与 `#pdf-viewport` 是阅读舞台中的相邻容器。样式规则同时为两者声明了 `display: block`，覆盖了浏览器对 `hidden` 属性的默认隐藏行为。因此打开 PDF 时，带有 `hidden` 属性的 EPUB 容器仍占据完整舞台高度，把 PDF 容器推到下一屏；阅读舞台的 `overflow: hidden` 随后将 PDF 页面完全裁掉。

现有端到端测试只检查 PDF 页数、文字层节点、缩放和页码状态。离屏页面仍能完成渲染并满足这些断言，所以测试没有发现视觉不可见问题。

## 修复范围

在阅读器样式中为 EPUB 与 PDF 根容器增加明确的隐藏规则：当容器带有 `hidden` 属性时必须使用 `display: none`。继续由现有 JavaScript 打开流程设置两个容器的 `hidden` 状态，不新增显示状态或类名。

修复不改变 PDF.js 渲染参数、PDF 文件读取、IndexedDB、阅读进度、缩放、文本层或 EPUB 连续滚动逻辑。

## 页面状态

- 欢迎页：两个阅读容器保持隐藏。
- EPUB/MOBI/AZW3：`#ebook-host` 可见，`#pdf-viewport` 不参与布局。
- PDF：`#pdf-viewport` 可见，`#ebook-host` 不参与布局。
- 返回书架或切换书籍：沿用现有关闭流程恢复隐藏状态。

## 回归测试

先扩展现有 PDF Edge E2E，使其在当前实现上因页面离开阅读舞台而失败。断言第一页满足：

1. 页面完成渲染；
2. 页面边界与 `#reader-stage` 的可视边界相交；
3. PDF 容器位于阅读舞台内部，而不是紧随隐藏的 EPUB 容器之后。

测试使用仓库现有的小型真实 PDF fixture，不提交用户提供的受版权保护文件。修复后运行该定向 E2E、全部单元测试、静态检查和完整 Edge E2E。

## 验收标准

- 用户提供的扫描版 PDF 首屏在根目录扩展中可见。
- 标准文本型 PDF 首屏可见，文字层、缩放、跳页与进度恢复继续工作。
- EPUB/MOBI/AZW3 阅读布局没有回归。
- 工作区只包含本次规格、测试与最小样式修复。
