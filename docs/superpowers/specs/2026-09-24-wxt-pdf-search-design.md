# WXT PDF 搜索迁移设计

## 背景与范围

WXT/Vue 已接管 PDF 加载、渲染、导航、缩放和进度，但 PDF 搜索仍由旧控制器负责。本阶段只迁移 PDF 搜索；PDF 批注留给下一独立阶段。电子书搜索、根目录稳定入口、AI 路由、schema v2 和持久化格式均保持不变。

## 目标

- Vue/Pinia 接管 WXT PDF 搜索输入、运行状态、结果、取消、跳转和匹配标记。
- 保持句子级上下文、页码结果、最多展示 300 条、未渲染页提示和新查询取消旧查询。
- PDF.js 会话继续独占文档、页面、渲染任务、缓存、缩放和进度资源。
- 搜索只读取当前会话已渲染的文本层，不向 store 或组件暴露 PDF.js 对象。
- 关闭、换书、错误、缩放重渲染和快速连续打开时清除过期结果及 DOM 标记。

## 非目标

- 不迁移 PDF 高亮与批注。
- 不迁移 EPUB、MOBI、AZW3 搜索。
- 不增加 OCR、语义搜索、全文预提取或持久搜索索引。
- 不启用 AI，不把 WXT 切换为稳定入口。

## 架构

### 会话边界

PdfSessionPort 提供只读搜索表面：页数、读取已渲染文本层以及类型化页码导航。端口不得返回 PDF 文档、页面、文本内容、渲染任务或缓存。PDF.js adapter 仍不得导入搜索、批注、持久化或 Vue 模块。

### 搜索服务

新增无持久化 TypeScript 服务，负责规范化查询、扫描已渲染文本层、复用现有句子上下文、生成 DOM Range 匹配标记、统计未渲染页、遵从 AbortSignal，并只清理自己创建的 .pdf-search-match。它不得访问 IndexedDB、BookRepository、PDF.js 或 Pinia。

### Pinia store

新增 PdfSearchStore，持有查询、idle/searching/ready/error 状态、页码与文本偏移结果、总匹配数、展示结果、未渲染页数、当前 AbortController 和会话 generation。旧 generation 或已取消查询不能更新状态。关闭、换书、错误和缩放重建文本层时清空搜索；跳转委托 PdfSessionStore.goTo(page)。

### Vue 与旧控制器

ToolsPanel.vue 在 PDF 会话下独占搜索表单、状态和结果；电子书会话仍走旧路径，同一提交不能同时触发两套监听器。结果沿用现有 CSS 和可访问标签。

旧控制器在 WXT PDF 会话活跃时不得处理搜索提交、结果点击或 PDF 搜索标记。现有 LegacyPdfTools 收窄为批注专用接口，直到下一阶段迁移批注。根目录入口行为不变。

## 数据流与竞态

1. 用户提交查询，store 取消上一查询并记录 PDF generation。
2. 服务逐页读取已渲染文本层；未渲染页只计数，不主动加载 PDF.js 页面。
3. store 只接收仍匹配当前 generation 且未取消的结果。
4. 点击结果通过 PDF 会话端口跳页。
5. 关闭、换书、错误或缩放时取消查询并移除标记。

空查询回到 idle。扫描期间文本层被移除时按未渲染处理，不产生未处理异常。搜索失败只影响搜索状态，不关闭阅读会话或写数据库。

## 测试与验收

- 服务测试：多页匹配、句子上下文、300 条上限、未渲染页、空查询、取消和标记清理。
- store 测试：新查询取消旧查询、拒绝旧 generation、跳转、关闭/错误/缩放清理。
- Vue 测试：PDF 搜索只由 Vue 处理，电子书搜索继续由旧路径处理。
- 架构测试：搜索服务不得导入 PDF.js、持久化、Vue；组件/store 不得直接访问引擎或 IndexedDB。
- 真实 Edge：真实 PDF 搜索、上下文、跳转、标记、快速查询取消、缩放、关闭重开和跨格式快速打开。
- 完整回归：WXT PDF、电子书、数据连续性和根目录稳定版。

## 发布约束

- 自动化测试与真实 Edge 验收全部通过后才更新路线图。
- 本阶段独立提交并推送到 main；WXT 仍不是稳定加载入口。
- 下一阶段再迁移 PDF 批注，不在本阶段顺带修改。
