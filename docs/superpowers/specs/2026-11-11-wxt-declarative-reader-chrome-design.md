# WXT 声明式阅读工作区设计

日期：2026-11-11

## 意图

继续缩小 WXT/Vue 迁移中的命令式 DOM 适配面。当前 `ReaderWorkspace.vue` 已拥有阅读工作区，却仍通过元素 ID 手工同步加载页、格式宿主、页码、进度和缩放状态，并跨组件为 PDF 缩放按钮注册原生监听器。这些状态已经存在于 Pinia，重复投影增加了更新顺序和卸载清理风险。

## 目标

- 加载中、错误、EPUB/PDF 宿主显隐、章节、页码、进度与缩放文本均由 Vue 模板直接派生 Pinia 状态。
- PDF 缩放工具栏由其所在的 `OverlayControls.vue` 直接读取 PDF Store 并调用动作。
- 保持现有 DOM ID、可访问属性、错误恢复、键盘行为和真实 Edge 测试契约。
- 减少 `ReaderWorkspace.vue` 对其自有 DOM 节点的查询和原生点击监听器。

## 非目标

- 不迁移 Foliate/PDF.js 引擎宿主查询；`main.ts` 仍在 Vue 挂载后取得明确宿主节点。
- 不改变根目录稳定版、IndexedDB schema、备份格式、AI 暂停状态或视觉设计。
- 不在本切片处理文件选择器、面板焦点管理或 `body` 类投影等组件外边界。

## 方案

1. **在现有组件内直接声明式绑定（采用）**：`ReaderWorkspace` 计算显示文本和 ARIA 值，`OverlayControls` 自己处理缩放。改动局部，沿用现有 Store 接口。
2. 新增统一 `ReaderChromeStore`：可以集中所有派生状态，但会复制现有 Ebook/PDF/Reader Store，形成第二投影层，本阶段不采用。
3. 保留 DOM 同步器并只补测试：短期改动最少，但无法推进 Vue 所有权迁移，也继续保留跨组件监听器，本阶段不采用。

## 行为约束

- 加载状态继续使用礼貌播报，错误状态继续使用即时警报和安全错误文案。
- EPUB 与 PDF 切换时只显示对应宿主；关闭后两者均隐藏且清理进度的 `aria-valuetext`。
- PDF 页码、总页数、进度和缩放必须随 Store 更新，且总页数未变化时不产生额外 DOM 文本变更。
- 所有 Vue 点击处理器继续阻断遗留监听器，避免同一操作执行两次。
- 60%–250% 的缩放边界继续由 PDF 会话适配器负责，组件只提交步进值或 100%。

## 验收

- 组件测试在工作区自有节点的 ID 查询被禁止时仍能挂载并响应 Store，证明状态投影不依赖命令式节点查找；现有控件路由测试继续证明 PDF 工具栏只执行一次动作。
- 现有 Vue 组件测试继续覆盖 EPUB/PDF 状态、加载/错误、页码/进度/缩放、关闭清理和重复监听隔离。
- `npm run check`、全部 Vitest、WXT 构建校验及相关真实 Edge EPUB/PDF 会话测试通过。
